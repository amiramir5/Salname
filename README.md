# سالنامه هوشمند و نوت‌برداری دیجیتال

یک سالنامهٔ جلالی ۱۰ماهه (۱ مهر ۱۴۰۵ تا ۳۱ تیر ۱۴۰۶) که با **قلم یا انگشت** روی تبلت پر می‌شود، دست‌خط را با **هوش مصنوعی** می‌خواند، از آن **مایندمپ** می‌سازد و **ساختارهای دوبعدی** مثل ساختار لوییس را به‌صورت تصویر نگه می‌دارد.

اگر نخواهی دست‌خطت اصلاً به متن تبدیل شود، دکمهٔ **«ساخت درخت از دست‌خط خودم»** خودِ دست‌خط را — بدون AI و بدون OCR — به‌شکل نمودار درختی می‌چیند.

روی گوشی و تبلت **نصب‌شدنی** است و **بدون اینترنت هم کامل کار می‌کند**.

## راه‌اندازی سریع

```bash
npm run serve      # → http://127.0.0.1:8080
```

> **مهم:** اپ را با این سرور باز کن، نه با دوبار کلیک روی `index.html`.
> حالت آفلاین و نصب‌شدنی از طریق `service worker` کار می‌کند و آن هم **فقط روی `http/https`** فعال می‌شود، نه روی `file://`.

### اجرای تست‌ها

```bash
npm test           # ۱۰۹ بررسی، بدون هیچ وابستگی
```

### انتشار

```
https://amiramir5.github.io/Salname/
```

مخزن روی GitHub Pages منتشر می‌شود (شاخهٔ `main`، پوشهٔ ریشه). هر `push` روی `main` به‌طور خودکار منتشر می‌شود و یک GitHub Action هم تست‌ها را اجرا می‌کند.

## قلم و مرورگر

**کوتاه:** اپ را با **Edge یا Chrome** باز کن و از منوی مرورگر **«نصب اپ»** را بزن. برای قلم، همین بهترین حالت ممکن است.

دلیلش یک API مرورگری است: اپ برای گرفتن حلقه‌های ریز حروفی مثل «م» و «و» و برای پرکردن دایره، از رویداد `pointerrawupdate` استفاده می‌کند. این رویداد **فقط در مرورگرهای کرومیوم** وجود دارد:

| مرورگر | `pointerrawupdate` | نتیجه با قلم |
|---|---|---|
| **Edge / Chrome** | ✅ دارد | ریزترین حرکت‌ها هم ثبت می‌شود |
| Firefox | ❌ ندارد | فقط `pointermove` می‌رسد؛ حلقه‌های تنگ ناقص درمی‌آیند |
| Safari (iPad) | ❌ ندارد | مثل فایرفاکس |

در فایرفاکس و سافاری اپ **کار می‌کند**، ولی چون نمونه‌برداری قلم کم‌تر است خط‌های ریز و سریع ناقص ثبت می‌شوند. این محدودیت خودِ مرورگر است، نه باگ اپ؛ هیچ کد جاوااسکریپتی نمی‌تواند رویدادی را که مرورگر نمی‌فرستد بسازد. (اپ در این حالت به `pointermove` + `getCoalescedEvents` برمی‌گردد و اگر آن هم لیست خالی بدهد، خودِ رویداد را استفاده می‌کند تا حرکت گم نشود.)

### نصب به‌عنوان اپ (توصیه‌شده)

1. `https://amiramir5.github.io/Salname/` را در **Edge** باز کن.
2. منوی `...` → **Apps → Install this site as an app** (در Chrome: **Install app**).
3. از این به بعد از آیکون نصب‌شده باز کن: پنجرهٔ مستقل دارد، بدون نوار آدرس، و `service worker` هم کامل فعال می‌شود.

اگر روزی خواستی از Microsoft Store پخشش کنی، [PWABuilder](https://www.pwabuilder.com/) همین نشانی را می‌گیرد و بستهٔ Store می‌سازد — چون `manifest` و `service worker` از قبل هست، کار اضافه‌ای لازم نیست.

## تنظیم کلید هوش مصنوعی

برای خواندن دست‌خط، اپ به کلید Google Gemini نیاز دارد:

1. از [Google AI Studio](https://aistudio.google.com/apikey) یک کلید رایگان بساز.
2. در اپ، از دکمهٔ **«هوش مصنوعی (Gemini)»** کلید را وارد کن.

کلید **فقط روی همین دستگاه** و در IndexedDB ذخیره می‌شود و هیچ‌وقت داخل کد یا مخزن نمی‌رود. (`const apiKey = ""` عمداً خالی است.)

> ⚠️ **هشدار امنیتی:** فایل بکاپی که از دکمهٔ «بکاپ» می‌گیری، کلید را هم در خودش دارد.
> اگر آن فایل را برای کسی فرستادی، کلیدت را از AI Studio **باطل و از نو بساز**.

## ساختار فایل‌ها

```
index.html                     کل اپ: مارک‌آپ + استایل + منطق (یک فایل)
sw.js                          service worker — کش آفلاین
manifest.webmanifest           معرفی اپ برای نصب روی خانهٔ گوشی
tailwind.config.js             تنظیم Tailwind برای بیلد استاتیک
tailwind.input.css             ورودی بیلد Tailwind
package.json                   فقط اسکریپت‌ها؛ هیچ وابستگی‌ای نصب نمی‌شود

assets/
  tailwind.css                 بیلد استاتیک Tailwind (~۲۵KB)
  fonts/vazirmatn/             فونت وزیرمتن (۹ وزن، woff2)
  katex/                       KaTeX — رندر فرمول ریاضی
  pdfjs/                       PDF.js — ایمپورت صفحهٔ PDF
  icons/                       آیکون‌های اپ (svg + png)

tests/salname.test.js          تست‌ها (Node خالی، بدون وابستگی)
tools/dev-server.js            سرور محلی توسعه
.github/workflows/ci.yml       اجرای خودکار تست‌ها روی هر push
```

**هیچ CDN و هیچ سرویس خارجی‌ای در کار نیست.** همهٔ کتابخانه‌ها داخل `assets/` هستند، پس اپ حتی وقتی `cdnjs` یا `jsdelivr` در دسترس نباشند (یا فیلتر باشند) هم کامل بالا می‌آید.

## کارهای رایج

### عوض کردن ظاهر

استایل‌ها در دو جا هستند: کلاس‌های Tailwind در خود `index.html`، و استایل‌های سفارشی داخل تگ `<style>`.

اگر کلاس **جدیدی** اضافه کردی، باید Tailwind را دوباره بیلد کنی، وگرنه آن کلاس بی‌اثر می‌ماند:

```bash
npm run build:css
```

### اضافه کردن فایل جدید به assets

بعد از افزودن فایل، این سه کار را انجام بده:

1. شمارهٔ `CACHE_VERSION` را در `sw.js` بالا ببر.
2. مسیر فایل را به آرایهٔ `PRECACHE` در `sw.js` اضافه کن.
3. `npm test` بزن — اگر فراموش کرده باشی، تست‌ها گیر می‌دهند.

### بالا بردن شمارهٔ نسخه

عدد `version` در `APP_BUILD` (بخش ۱۷) را زیاد کن. این عدد پایین مودال هوش مصنوعی نشان داده می‌شود و تنها راه مطمئن برای تشخیص «کش قدیمی» از «باگ واقعی» است.

### تست کردن یک تغییر

```bash
npm test
```

تست‌ها توابع را **از خود `index.html` استخراج می‌کنند**، نه از یک نسخهٔ کپی. پس اگر تستی سبز شد، یعنی همان کدی که منتشر می‌شود درست است — نه یک نسخهٔ قدیمی.

## نکات ظریفی که وقت زیادی گرفتند

اینها را نخوانی، ممکن است دوباره همان باگ‌ها را بسازی:

**۱) راست‌به‌چپ و فرمول‌ها (مهم‌ترین)**
هر قطعهٔ لاتین که داخل متن فارسی بیاید باید **یک `isolate` کامل** باشد. اگر فرمول تکه‌تکه شود (مثل `CO(` و `)۲`)، داخل پاراگراف راست‌به‌چپ **جابه‌جا و معکوس** می‌شود. به همین دلیل `chemPattern` طوری تنظیم شده که هر فرمول را **یک‌جا** بگیرد. تست بخش ۴ دقیقاً همین را نگه می‌دارد.

**۲) ارقام**
کاربر ارقام فارسی می‌بیند ولی همه‌جای کد باید با ارقام لاتین حساب کند. تبدیل فقط در لحظهٔ نمایش انجام می‌شود (`toPersianDigits`).

**۳) مختصات تصویر ساختار از سمت راست است**
مقدار `x` در کادر ساختار (۰ تا ۱۰۰۰) از **لبهٔ راست** شمرده می‌شود، چون خودِ تصویر برای یک مدل فارسی‌فهم همین‌طور توصیف می‌شود. تبدیلش در `structureBoxToSourceRect` است و حاشیهٔ برش عمداً ۵٪ گرفته شده تا لبهٔ نقاشی بریده نشود.

**۴) `py-0.2` کلاس معتبری نیست**
در سه جا کلاس `py-0.2` نوشته شده که در مقیاس پیش‌فرض Tailwind وجود ندارد و از اول هم بی‌اثر بوده. اگر خواستی درستش کنی، `py-0.5` جای درستی است — ولی ظاهر کمی تغییر می‌کند.

**۵) کش service worker**
نحوهٔ بارگذاری **شبکه‌اول** است: وقتی آنلاینی همیشه نسخهٔ تازه می‌گیری و کش فقط برای آفلاین است. پس دیگر نیازی به `?v=۳` نیست. اما فایل‌های `assets/` **کش‌اول** هستند — برای همین بعد از هر تغییر در `assets/` باید `CACHE_VERSION` را بالا ببری.

**۶) لایهٔ زندهٔ جوهر هم باید `dpr` بخورد**
`canvas-interaction` قبلاً ۱:۱ ساخته می‌شد و روی نمایشگرهایی با `devicePixelRatio` بزرگ‌تر از ۱، مرورگر آن بوم را بزرگ‌نمایی می‌کرد و لبهٔ خط محو می‌شد. نتیجه: خط **حین نوشتن** پهن‌تر از خط نهایی دیده می‌شد و بعد از برداشتن قلم «درست» می‌شد. اندازه‌گیری واقعی روی همین دستگاه: قلم ۴ پیکسلی ۵.۳۳ پیکسل رد می‌گذاشت، ولی خط نهایی ۴ بود. حالا هر چهار بوم یک `setTransform(dpr, …)` دارند و هر دو دقیقاً ۴ اندازه‌گیری می‌شوند.

**۷) اندازهٔ پاک‌کن فقط یک جا تعریف شده**
`ERASER_RADIUS` (بالای `resizeCanvases`) هم برای حلقهٔ روی صفحه و هم برای تست برخورد استفاده می‌شود، تا آن‌چه می‌بینی دقیقاً همان چیزی باشد که پاک می‌شود. عدد ۹ است؛ کم و زیادش کنی هر دو با هم عوض می‌شوند.

**۸) نشانگر قلم را خودمان می‌کشیم**
`#canvas-interaction` حالا `cursor: none` دارد و جای آن یک نقطهٔ کوچک روی بوم کشیده می‌شود (`drawPenCursorPreview`). اگر از نشانگر خود سیستم‌عامل استفاده کنیم، اندازه‌اش را سیستم تعیین می‌کند و روی نمایشگر پرچگال بزرگ و زمخت دیده می‌شود. فقط ابزار **دست/جابه‌جایی** استثناست و `data-cursor="grab"` می‌گیرد.

**۹) قاعدهٔ سراسری `canvas` روی بوم‌های تازه هم اثر می‌گذارد**
در `<style>` نوشته شده `canvas { position: absolute; top: 0; left: 0; width: 100%; height: 100%; }` که برای بوم‌های تمام‌صفحهٔ نقاشی است. هر بوم دیگری که داخل صفحه بسازی این را ارث می‌برد و روی محتوای اطرافش می‌افتد — مثل بوم دست‌خط داخل کارت‌های درخت. برای همین `.mindmap-node-ink` صریحاً `position: static` دارد و تست بخش ۸ نگهش می‌دارد.

**۱۰) درختِ دست‌خط چطور ساخته می‌شود (هیچ OCR و هیچ مدلی در کار نیست)**
گروه‌بندی روی دو واقعیت دست‌خط فارسی بنا شده: نقطه‌های پ/ت/چ/ج/ق/ی **خط جداگانه‌اند** ولی حرف جدا نیستند، و فاصلهٔ بین دو کلمه خیلی کمتر از فضای خالی بین دو مطلب جداگانه است. پس اول خط‌ها فقط از روی «بدنهٔ حروف» ساخته می‌شوند، بعد هر نقطه به نزدیک‌ترین خط می‌چسبد (تا هرگز کارت مستقل نشود)، و داخل یک خط فقط یک فضای خالی **واقعاً بزرگ** (حداقل ۸۵ پیکسل) کارت جدید می‌سازد — فاصلهٔ بین کلمات هیچ‌وقت مرز کارت نیست. آستانه‌ها از اندازهٔ خودِ دست‌خط حساب می‌شوند. بعد بلوک‌ها به ترتیب خواندن فارسی (بالا به پایین، راست به چپ) پیمایش می‌شوند و بلوکی که لبهٔ راستش از بلوک بالایش چپ‌تر باشد، فرزند آن می‌شود. اگر هیچ تورفتگی‌ای نباشد، بلوک اول ریشه می‌شود و بقیه فرزندش — تا نتیجه در هر حال یک درخت باشد. هیچ نوشته‌ای روی برگه پاک نمی‌شود و اگر دوباره دکمه را بزنی، خط‌هایی که قبلاً داخل کارتی رفته‌اند دوباره کارت نمی‌سازند.

**۱۱) شاخه‌های درخت منحنی‌اند، نه خط مورب**
`drawMindMapConnectors` از یک نقطهٔ انشعاب روی والد، با `bezierCurveTo` منحنی نرم می‌کشد. اگر مستقیم بکشی، دو فرزندِ یک والد شبیه یک خط بلندِ شکسته دیده می‌شوند و درخت شبیه تارعنکبوت می‌شود. ضخامت شاخهٔ سطح اول ضخیم‌تر است و سرِ والد یک حلقهٔ سفید-رنگ دارد.
